# Cryptographic Audit Ledger (Blockchain)

For the SIH26 PS 024 Coal Mine Governance system, we are implementing an **Immutable Audit Ledger** using a Solidity smart contract. This provides mathematical proof that safety violation tickets and inspection reports were not tampered with or deleted by mine managers trying to avoid regulatory fines.

## 1. Why Blockchain?

A standard MongoDB database is mutable. A database administrator with the right credentials can easily run `db.tickets.deleteOne({ _id: "violation_123" })` or alter the text of an inspector's report. 

By integrating a smart contract, we create a system where:
1. Every time a new ticket is generated (via CV, IoT, or manual inspection), the Python backend calculates the **SHA-256 hash** of the ticket's JSON data.
2. The backend uses `web3.py` to send this hash to our deployed Solidity smart contract.
3. The hash is permanently written to a public testnet ledger (like Polygon Mumbai/Amoy or Sepolia).
4. **Audit Time:** A government regulator can take the tickets currently in the MongoDB, hash them, and compare them against the hashes on the blockchain. If a ticket was altered or deleted from MongoDB, the blockchain will expose the discrepancy.

## 2. Smart Contract Implementation (`AuditLedger.sol`)

Just like your previous `NeelKadam` project, this will be developed using **Hardhat**.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

/// @title Coal Mine Cryptographic Audit Ledger
contract AuditLedger {
    address public regulatoryAuthority; // e.g., DGMS or CPCB
    uint256 public nextReportId = 1;

    struct InspectionReport {
        uint256 id;
        string reportHash;    // The SHA-256 hash of the JSON ticket data
        string mineId;        // Which mine this occurred at
        uint256 timestamp;
        address loggedBy;     // Wallet of the backend system or inspector
        bool isResolved;
    }

    // Maps a unique report ID to the report data
    mapping(uint256 => InspectionReport) public reports;
    
    // Allows regulators to fetch all report IDs for a specific mine
    mapping(string => uint256[]) public mineReports; 

    // Events for the backend to listen to
    event ReportLogged(uint256 indexed id, string mineId, string reportHash);
    event ReportResolved(uint256 indexed id, string resolutionHash);

    constructor() {
        // The wallet that deploys the contract is the ultimate regulatory authority
        regulatoryAuthority = msg.sender;
    }

    /// @notice Logs a new inspection/violation hash to the blockchain
    function logReport(string memory _mineId, string memory _reportHash) external {
        uint256 reportId = nextReportId++;
        
        reports[reportId] = InspectionReport({
            id: reportId,
            reportHash: _reportHash,
            mineId: _mineId,
            timestamp: block.timestamp,
            loggedBy: msg.sender,
            isResolved: false
        });

        mineReports[_mineId].push(reportId);
        
        emit ReportLogged(reportId, _mineId, _reportHash);
    }

    /// @notice Marks a violation ticket as resolved (requires proof hash)
    function resolveReport(uint256 _reportId, string memory _resolutionHash) external {
        require(reports[_reportId].id != 0, "Report does not exist");
        require(!reports[_reportId].isResolved, "Already resolved");

        reports[_reportId].isResolved = true;
        
        // Emitting the resolution hash provides proof of the CAPA action taken
        emit ReportResolved(_reportId, _resolutionHash);
    }

    // ------------------------
    // View Functions
    // ------------------------
    
    function getReportsByMine(string memory _mineId) external view returns (uint256[] memory) {
        return mineReports[_mineId];
    }
    
    function getReportDetails(uint256 _reportId) external view returns (InspectionReport memory) {
        return reports[_reportId];
    }
}
```

## 3. Workflow Integration

### Folder Structure
This code will live in the `blockchain/` folder at the root of the monorepo:
```text
blockchain/
├── contracts/
│   └── AuditLedger.sol     # The smart contract above
├── scripts/
│   └── deploy.js           # Hardhat deployment script
├── test/
│   └── AuditLedger.js      # Chai/Mocha tests
├── hardhat.config.js       # Configured with Polygon/Ethereum testnet RPC URLs
└── package.json            # Hardhat dependencies
```

### How the Backend Interacts
Inside your `backend/src/blockchain/blockchain_client.py`:
1. Load the compiled ABI (`AuditLedger.json`) generated by Hardhat.
2. Initialize a connection using `web3.py` and a private key (funded with testnet MATIC/ETH).
3. When a ticket is created in FastAPI, trigger `contract.functions.logReport(mine_id, sha256_hash).buildTransaction()` and broadcast it.
